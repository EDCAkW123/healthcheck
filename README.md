# Проверка приоритета HEALTHCHECK в Timeweb App Platform

Минимальное тестовое приложение без внешних Python-зависимостей.
Для сборки нужны `Dockerfile` и `app.py` в одной директории.

## Настройки в панели управления

- Способ деплоя: Dockerfile.
- Порт приложения: `8080`.
- Ошибочный путь проверки состояния: `/unhealthy` — возвращает HTTP `503` и `{"status":"error"}`.
- Корректный путь проверки состояния: `/health` — возвращает HTTP `200` и `{"status":"ok"}`.
- Главная страница приложения: `/` — возвращает HTTP `200`.

В поле пути указывайте только путь, без домена и порта.
В Dockerfile проверяется только корректный адрес `http://127.0.0.1:8080/health`.
Эндпоинт `/unhealthy` имитирует ошибку, но само приложение продолжает работать.
Поддерживаются `GET` и `HEAD`: коды и заголовки совпадают, но у `HEAD` нет тела ответа.
Команда `curl -i` выполняет `GET`, а `curl -I` — `HEAD`.
Для проверки опубликованного приложения используйте сразу `https://`,
чтобы не получать промежуточное перенаправление HTTP → HTTPS.

## Сценарий проверки

1. Разверните приложение с путём `/health` в ПУ и убедитесь, что деплой успешен.
2. Измените путь в ПУ на `/unhealthy`. Сохранение запускает новый деплой.
3. Проверьте результат деплоя и логи: по документации встроенный `HEALTHCHECK`
   имеет приоритет, поэтому `/unhealthy` из ПУ должен игнорироваться,
   а приложение — успешно проходить проверку через `/health`.
4. Откройте `/health` и `/unhealthy` на домене приложения либо проверьте их через
   `curl -i`, чтобы увидеть коды `200` и `503` соответственно.

Это ожидаемое поведение по документации; фактический результат нужно проверить в Timeweb.
При запросах в stdout/stderr приложения выводятся путь и HTTP-код.

Источник: [Путь проверки состояния — Timeweb Cloud](https://timeweb.cloud/docs/apps/healthcheck-path).

## Локальный запуск

```sh
docker build -t healthcheck-demo .
docker run -d --name healthcheck-demo -p 8080:8080 healthcheck-demo
curl -i http://localhost:8080/health
curl -i http://localhost:8080/unhealthy
docker inspect --format '{{json .State.Health}}' healthcheck-demo
```

После первой успешной внутренней проверки статус контейнера должен стать `healthy`.
Для удаления тестового контейнера: `docker rm -f healthcheck-demo`.
